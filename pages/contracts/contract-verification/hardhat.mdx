# Verifying a Smart Contract on ApeChain with Hardhat

## Introduction
Verifying a smart contract on the blockchain is crucial for ensuring its transparency, security, and facilitating interaction for both users and developers. Hardhat is a versatile tool designed for compiling, testing, deploying, and verifying smart contracts.

This guide will walk you through verifying your smart contract on [ApeScan](https://apescan.io/) for ApeChain Mainnet and the Curtis Testnet using Hardhat. ApeScan's API is compatible with the Etherscan API, so Hardhat's built-in Etherscan verifier works with it out of the box.

## Prerequisites
Before you begin the verification process, make sure you have the following:

- **Hardhat 3 Installed**: This is essential for compiling, deploying, and verifying your smart contract. Using Hardhat 2? See [Using Hardhat 2](#using-hardhat-2).
- **Node.js and NPM**: Hardhat operates on Node.js, and NPM (Node Package Manager) is used to install necessary packages.
- **ApeScan API Key**: Sign in on [ApeScan](https://apescan.io/api-keys) with your wallet and create a free API key. The same key works for Mainnet and Curtis.
- **Deployed Smart Contract**: Ensure your smart contract is already deployed on ApeChain or Curtis. If it isn't, refer to the guide on Deploying a Smart Contract.

## Step 1: Installing Hardhat Verify Package
The `@nomicfoundation/hardhat-verify` plugin is included in both Hardhat toolboxes (`hardhat-toolbox-viem` and `hardhat-toolbox-mocha-ethers`). If you are not using a toolbox, install it in your project's root directory:

```bash copy
npm install --save-dev @nomicfoundation/hardhat-verify
```

## Step 2: Configuring Hardhat
Next, add the ApeChain networks and point Hardhat's Etherscan verifier at ApeScan in your ```hardhat.config.ts``` file.

<Callout type="info">The verifier config key is `etherscan` because Hardhat names it after the API standard. The `chainDescriptors` below send those requests to ApeScan instead of Etherscan.</Callout>

```ts copy
import hardhatToolboxViemPlugin from "@nomicfoundation/hardhat-toolbox-viem";
import { configVariable, defineConfig } from "hardhat/config";

export default defineConfig({
  plugins: [hardhatToolboxViemPlugin],
  solidity: "0.8.28",
  networks: {
    apechain: {
      type: "http",
      url: "https://rpc.apechain.com/http",
      accounts: [configVariable("PRIVATE_KEY")],
    },
    curtis: {
      type: "http",
      url: "https://curtis.rpc.caldera.xyz/http",
      accounts: [configVariable("PRIVATE_KEY")],
    },
  },
  chainDescriptors: {
    33139: {
      name: "ApeChain",
      blockExplorers: {
        etherscan: {
          name: "ApeScan",
          url: "https://apescan.io",
          apiUrl: "https://api.apescan.io/api",
        },
      },
    },
    33111: {
      name: "Curtis",
      blockExplorers: {
        etherscan: {
          name: "ApeScan",
          url: "https://curtis.apescan.io",
          apiUrl: "https://curtis.apechain.com/api",
        },
      },
    },
  },
  verify: {
    etherscan: {
      apiKey: configVariable("APESCAN_API_KEY"),
    },
  },
});
```

`configVariable` keeps your private key and API key out of the config file. Store them with Hardhat's encrypted keystore:

```bash copy
npx hardhat keystore set PRIVATE_KEY
npx hardhat keystore set APESCAN_API_KEY
```

## Step 3: Verifying Your Contract

Once your project is configured for verification, you can proceed to verify your smart contract on ApeChain Mainnet or Testnet. Replace `<contract-address>` with the actual address of your deployed contract, and append any constructor arguments after it.

### For Mainnet

```bash copy
npx hardhat verify --network apechain <contract-address>
```

### For Testnet

```bash copy
npx hardhat verify --network curtis <contract-address>
```

This command submits your contract's source code and metadata to ApeScan. Once successfully verified, your contract's source code will be publicly accessible on ApeScan, linked to its on-chain address.

<Callout type="info">`hardhat verify` submits to every verifier that is enabled in your config, which by default includes Blockscout and Sourcify as well. To verify on ApeScan only, run `npx hardhat verify etherscan --network apechain <contract-address>`.</Callout>

## Using Hardhat 2

On Hardhat 2, use `@nomicfoundation/hardhat-verify@hh2` and add ApeScan as custom chains under the `etherscan` key:

```ts copy
import "@nomicfoundation/hardhat-toolbox";
import type { HardhatUserConfig } from "hardhat/config";

const config: HardhatUserConfig = {
  solidity: "0.8.28",
  networks: {
    apechain: {
      url: "https://rpc.apechain.com/http",
      accounts: [process.env.PRIVATE_KEY!],
    },
    curtis: {
      url: "https://curtis.rpc.caldera.xyz/http",
      accounts: [process.env.PRIVATE_KEY!],
    },
  },
  etherscan: {
    apiKey: {
      apechain: process.env.APESCAN_API_KEY!,
      curtis: process.env.APESCAN_API_KEY!,
    },
    customChains: [
      {
        network: "apechain",
        chainId: 33139,
        urls: {
          apiURL: "https://api.apescan.io/api",
          browserURL: "https://apescan.io",
        },
      },
      {
        network: "curtis",
        chainId: 33111,
        urls: {
          apiURL: "https://curtis.apechain.com/api",
          browserURL: "https://curtis.apescan.io",
        },
      },
    ],
  },
};

export default config;
```

The verify commands are the same as above.

## Conclusion
Verifying your smart contract not only strengthens your project's transparency and credibility but also greatly enhances the user experience by making interactions and verifications more straightforward. By following the steps in this guide, developers can ensure their contracts are verified and available for public scrutiny, contributing to a more secure and trustworthy ecosystem.
